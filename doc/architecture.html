🎯 What does this system do?
📊

Stage 2 Screener

Identifies stocks from the Nifty Total Market universe that are breaking out of consolidation into an uptrend — the "Stage 2" phase described by Stan Weinstein. Scores each stock out of 8 based on price, volume, moving average conditions, and base formation. Also detects Weinstein Retest patterns (breakout → pullback → bounce with volume dryup).

🚀

Momentum Screener

Ranks stocks by risk-adjusted return (Sharpe ratio) across multiple timeframes — 3, 6, 9, and 12 months. Identifies stocks with consistent, smooth upward momentum. Includes a Phase Chart showing each stock's current Weinstein stage over time for the full universe.

🗄️

Parquet-Backed Cache

All OHLCV data is stored locally in Parquet files — no external database required. Three tiers: in-memory dict (instant), Parquet on disk (persists across restarts), and live yfinance fetch (only for missing dates). Atomic writes ensure crash safety.

📈

Portfolio Backtester

Simulates 6 simultaneous portfolio strategies over up to 10 years of NSE data. Models India's Capital Gains Tax (LTCG / STCG with 8-year carry-forward loss set-off), transaction costs, brokerage, and position sizing. Includes walk-forward validation and a rebalance-level debug log.

📡

Live Signal

Generates the current rebalance signal — which stocks to buy, hold, and sell — based on the screener's live scores and a selected strategy configuration. Outputs exact share quantities and estimated trade values ready for execution.

📋 The 8-Point Stage 2 Scoring System
🟢 6–8 Strong Stage 2 🟡 4–5 Likely Stage 2 🟠 2–3 Early / Weak ⚪ 0–1 Not Stage 2
#ConditionWhat it checks
1Volume SurgeToday's volume is 2× or more of the recent 10-day average — institutional buying signal
2Higher HighClose broke above the highest high of the past 50 days — price expanding upward
3Higher LowRecent 20-day floor is above the 50-day floor from 50 bars ago — rising support
4MA50 RisingPrice is above 50-day average and that average itself is trending up over 50 days
5MA200 RisingPrice is above 200-day average and that average is trending up — long-term health
6Above MA150Price above the 150-day average — medium-term trend confirmation
7MA StackMA50 > MA150 > MA200 — the "golden alignment" of moving averages
8ConsolidationClose-to-close range over last 20 days is <15% of the period low — base formation in progress
+Retest ★Bonus flag (not counted in score): Stock broke out on volume within last 20 days, pulled back to breakout level with volume contraction, and has bounced ≥2% above it
📡 Where does the data come from?
🌐

Yahoo Finance (yfinance)

Daily end-of-day OHLCV data for all NSE stocks. Incremental syncs fetch only missing dates; first run downloads ~2 years of history. Data stored in Parquet and refreshed automatically when stale.

📁

constituents.json

Symbol lists for Nifty 50, Next 50, Midcap 150, Smallcap 250, and Microcap 250. Updated manually on index rebalances. Used to tag each stock with its index membership.

📅

nse_holidays.json

NSE trading holiday calendar. Used to resolve the last valid trading day and skip weekends and holidays when generating rebalance dates.

🛡️

compositions.parquet

Historical index compositions by date — records which stocks were actually in the Nifty universe on each past date. Used by the backtester to prevent look-ahead bias (survivorship-bias mitigation).

🔑 Key Implementation Notes
3-Tier Cache Architecture (Screener) _mem_cache is a module-level dict with "stage2" and "momentum" slots. Stage 2 is keyed only by trading date (no TTL — once computed for a given day it never expires in-process). Momentum adds a "ts" timestamp and expires after 1 hour. The Parquet tier stores scored results in stage2_cache.parquet and momentum_cache.parquet keyed by date; these persist across Streamlit process restarts. No external database is used.
Session Isolation via user_token Each Streamlit session gets a UUID user_token on first render (stored in st.session_state). All jobs are keyed by (user_token, kind) in the JobRegistry. This prevents one user's backtest result being returned to another user's session. The UI polls registry.latest(token, kind) on every rerender to pick up progress events and the final result.
Atomic Parquet Writes All Parquet files are written via _write_parquet_atomic(df, path): write to a temp file in the same directory, then os.replace(tmp, path). On POSIX this is an atomic rename; on Windows it is close-to-atomic. This prevents reading a half-written file after a crash or Streamlit Cloud worker restart. Float32 is used for price columns; a ×0.9999 tolerance is applied in check_weinstein_retest() to avoid float32→float64 equality failures on Parquet round-trip.
Survivorship-Bias Mitigation compositions.parquet records which symbols were in each Nifty index on each historical rebalance date. Before ranking at each backtest date, rank_universe_at_date() filters symbol_data to only include symbols that were actually in the index at that point in time. This prevents the backtest from benefiting from hindsight knowledge of which stocks survived to be included in today's universe.
India CGT Tax Model Financial year runs April–March. Each disposal is classified as Short-Term (<12 months held) or Long-Term (≥12 months). Within each FY: ST losses first offset ST gains, then LT gains; LT losses only offset LT gains. Remaining losses carry forward up to 8 FYs (oldest consumed first). Tax is applied at STCG rate (default 20%) and LTCG rate (default 12.5%) configured by the user. Tax is deducted from NAV at FY end, reducing the compounding base for subsequent years.
⚠️ Known Quirks & Limitations • backtest_delta.parquet accumulates indefinitely — there is no automatic rotation. Monitor disk usage over time.
• compositions.parquet staleness is reported as a warning, not a hard block — a stale file silently degrades anti-survivorship-bias protection.
• The ThreadPoolExecutor has a fixed cap of 4 workers. Long backtests will queue; there is no backpressure signal to the UI beyond "Loading…".
• Float32 precision loss from Parquet round-trips is handled by the ×0.9999 tolerance in retest detection, but may affect other strict equality comparisons if added later.
🚀 Running the App

Install

pip install -r requirements.txt

Seed backtest data (first time)

python scripts/refresh_backtest_parquet.py
python scripts/refresh_screener_parquet.py

Run screener

streamlit run app.py

Run backtester

streamlit run app_backtest.py

No DATABASE_URL required. The current architecture uses only local Parquet files and yfinance. There is no PostgreSQL dependency. The .env.example file's DATABASE_URL reference is a historical artefact from a prior architecture and can be ignored.
